# libsortition: 抽選アルゴリズム（概要）

詳しい仕様は英語の [SPEC.md](SPEC.md) にあります。ここでは要点だけを日本語で書きます。

## 約束

同じ候補、同じ seed、同じ賞の分け方なら、どの実装（Rust、Python、Ruby、Node.js、WebAssembly、PHP、CLI）でも、同じ当選者になります。抽選の記録（`sortition draw --record`）は、あとで同じ抽選を繰り返せて初めて意味があるので、この規則は約束です。

この規則（SPEC.md の 3〜8 章）の名前は **`libsortition-draw/1`** です。結果が変わりうる変更をするときは、名前を新しくします（`libsortition-draw/2`）。記録にはこの名前が入るので、検証するときに別の版のアルゴリズムで確かめてしまうことはありません。

## 手順

1. **seed**: seed の文字列の SHA-256 が「コミット値」（抽選の前に公開する）。seed は、そのダイジェストの先頭 8 バイトをリトルエンディアンで読んだ `u64`。
2. **乱数**: seed ありは xoshiro256\*\*（SplitMix64 で初期化。再現できるが暗号論的ではない）。seed なしのセッションは、OS から取った鍵の ChaCha20（暗号論的）で、鍵と読んだ位置を保存状態に含める。
3. **範囲の乱数**: `below(bound)` は、`zone` 以下の値だけを採る棄却法で、剰余の偏りをなくす。
4. **k 個を引く**: 疎な Fisher–Yates。`i = 0..k-1` について `j = i + below(n - i)` を決めて入れ替える。分けて引いても、一度に引いたのと同じ並びになる。
5. **候補の ID**: `SHA256("libsortition/candidate/v1" || 0x00 || バイト列 || LE64(出現番号))`。同じバイト列が複数あっても、先頭から数えた出現番号で別の ID になる。ID は並び順に依らない。
6. **並べ方**: 候補を ID の昇順に並べたものが標準の順序。その上の位置を引くので、入力の並びが違っても同じ候補が当選する。候補集合の指紋は `SHA256("libsortition/set/v1" || 0x00 || LE64(件数) || 昇順の ID の連結)`。
7. **賞**: 合計人数を一度に引いて、先頭から賞ごとに切り分ける（「1 つ目を引き、残りから次を引く」と同じ）。
8. **セッション**: 引いた結果、入れ替えの表、乱数の位置を持ち、続きから引く。羃等キー付きの再送は、状態を変えずに前回の結果を返す。保存状態（JSON）と、封をしたトークン（XChaCha20-Poly1305）の形式も SPEC.md に書いてある。

位置で引く入口（`draw(n, k)`、テキストや JSON / YAML / TOML からの抽選）は ID を使わないので、結果はリストの並びに依ります。当選者が並びに依ってはいけないときは、候補（`draw_items` など）の関数を使ってください。
